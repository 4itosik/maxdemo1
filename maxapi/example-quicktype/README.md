# Пример использования `maxapi/gen/quicktype`

Сквозной сценарий на сгенерированных структурах: бот обновляет свою подписку
на webhook, принимает события и отвечает на них.

```
example-quicktype/
├── maxclient/   HTTP-клиент: подписки и отправка сообщений
├── webhook/     приём событий и диспетчеризация по update_type
└── cmd/echobot/ связка: подписался → слушает → отвечает
```

Отдельный Go-модуль с `replace maxapi => ../gen/quicktype`, чтобы рукописный код
примера не смешивался со сгенерированным.

## Запуск

```bash
export MAX_BOT_TOKEN=…             # токен бота из @MasterBot
export MAX_WEBHOOK_URL=https://…   # публичный HTTPS-адрес этого процесса
export MAX_WEBHOOK_SECRET=…        # 5..256 символов [A-Za-z0-9_-]
go run ./cmd/echobot
```

Max требует HTTPS, поэтому локально процесс ставят за туннель или
терминирующий TLS прокси. Флаг `-addr` задаёт адрес, который слушает сам
процесс (по умолчанию `:8080`).

```bash
go test ./...     # ничего не отправляет в сеть: Max Bot API играет httptest.Server
```

## Что показывает клиент

`maxclient` не объявляет ни одной структуры тела — всё берётся из `maxapi`:

```go
_, err := client.Subscribe(ctx, maxapi.SubscriptionRequestBody{
    URL:         "https://bot.example-quicktype.ru/hook",
    Secret:      &secret,
    UpdateTypes: []string{"message_created", "message_callback"},
})

result, err := client.SendMessage(ctx, maxclient.ToChat(chatID), maxclient.TextMessage("привет"))
```

В этом весь смысл кодогенерации: правка в `*.tsp` доезжает до клиента через
`make gen-quicktype`, а не через синхронизацию структур руками.

Три частности, за которые пришлось платить кодом:

- **Токен уходит в заголовке `Authorization`.** Контракт допускает и
  query-параметр `access_token` (`securitySchemes.ApiKeyAuth`), но query
  попадает в access-логи прокси, а заголовок — нет.
- **`ToUser`/`ToChat` вместо двух полей.** У `POST /messages` адресат — это
  два взаимоисключающих необязательных query-параметра; конструкторы не дают
  задать оба или ни одного. Случай «ни одного» закрыт тестом: клиент
  возвращает ошибку, не сходив в сеть.
- **`EnsureSubscription` — три вызова, а не один.** `PUT /subscriptions` в
  контракте нет: есть `GET`, `POST` и `DELETE`. Повторный `POST` на тот же
  URL безопасен и обновляет `update_types` и `secret`, поэтому подписка
  ставится всегда, а удаляются только посторонние адреса.

Ошибки вне 2xx разбираются в `maxapi.Error` и приезжают как `*APIError` —
с `Code` и `Message` из контракта, а не как `map[string]any`.

## Что показывает webhook-сервер

Это место, где сгенерированных структур **не хватает**, и ради него пример и
написан. quicktype не порождает `UnmarshalJSON` с диспетчеризацией по
дискриминатору, поэтому `maxapi.Update` — плоская структура: поля всех
шестнадцати типов событий собраны в одну и почти все необязательны.

Разбор идёт в два шага:

1. тело разбирается в `maxapi.Update`, чтобы прочитать `update_type`;
2. **то же тело** разбирается второй раз в конкретный тип варианта —
   `maxapi.MessageCreatedUpdate`, `maxapi.MessageCallbackUpdate`.

Второй разбор стоит дёшево (тело уже в памяти) и снимает весь пласт проверок
на nil: в `MessageCreatedUpdate` поле `Message` — значение, а не указатель,
потому что в этом событии оно обязательно. Прикладной код получает

```go
MessageCreated: func(ctx context.Context, u maxapi.MessageCreatedUpdate) error {
    chatID := u.Message.Recipient.ChatID   // без проверки u.Message != nil
    ...
}
```

Разобраны два типа событий, нужные echo-боту; остальные четырнадцать доходят
до `Handler.Other` плоским `Update` и дописываются по тому же образцу —
добавить `case` в `dispatch` и поле в `Handler`.

Ещё две вещи, которые видно только на живом трафике:

- **Секрет сверяется за постоянное время** (`crypto/subtle`): сравнение с
  ранним выходом позволило бы подобрать общий секрет побайтово по времени
  ответа.
- **Битое тело подтверждается двухсоткой, ошибка обработчика — пятисоткой.**
  Max повторяет доставку на не-2xx. Битое тело при повторе останется битым,
  так что 500 на него — вечный цикл повторов; а вот упавшая запись в БД —
  ровно тот случай, когда повтор нужен.

## Тесты

17 тестов, сети не касаются. Тело `message_created` в них — записанное с
живого Max (тот же образец, что в `gen/quicktype/models_test.go` и
`maxmoc/internal/core/live_sample_test.go`), поэтому проверяется в том числе
разрядность `seq`: значения порядка 1.17e17 выше JSON-safe 2^53−1.

`cmd/echobot/main_test.go` собирает обе половины вместе: webhook-сервер
принимает событие, обработчик отвечает через HTTP-клиент, а роль Max Bot API
играет `httptest.Server`.
